# 我的待办清单

一个单文件的待办事项网页：打开即用，不需要安装、不需要联网、不需要构建。

## 用法

- 直接下载 `index.html` 双击用浏览器打开；或
- 访问 GitHub Pages 部署后的在线地址（见下方「开启 GitHub Pages」）

## 说明站

仓库里另有一份讲这个页面的说明小站，同样零依赖、零 CDN、双击 `site/index.html` 即开（在线：`https://<你的用户名>.github.io/<仓库名>/site/`）：

- **总览**（`site/index.html`）：一页看清它有哪些能力，页面上的数字（模块数、功能条数、常量数、泳道数、方块数、连线数）是运行时从 `site/assets/data.js` 的数组长度算出来的，不是手写死的。
- **功能清单**（`site/features.html`）：按页面区块归纳成 8 个模块共 40 条能力，左侧目录可跳转并随滚动高亮，顶部搜索框按关键词逐条过滤。
- **业务流程图**（`site/flow.html`）：7 条泳道、45 个方块、56 条连线（其中 21 条带标签）的完整流程图，可缩放、可点选方块高亮相关连线、可打印。
- **数据与架构**（`site/data.html`）：6 条存储与边界说明 + 15 行关键常量，每行第三列给的是源码里的依据。

全站支持浅色/深色，主题偏好存在 `localStorage` 的 `flowdoc.theme`，和待办页自己的 `todo.*` 键互不影响。描述一律以线上 `index.html` 源码为准，不含推测。

说明站的动效与线上页面共用同一套纪律（`site/assets/tokens.css` 里的 `--ease-enter` / `--dur-enter` / `--dur-hover` / `--dur-panel` 四个变量，取值与 `index.html` 逐字相同）：首屏 `fade-up` 进场，其余板块由 `site.js` 给 `.shell` 的直属子块补上 `.reveal` 后用同一个 `IntersectionObserver` 参数（`threshold: .12`、`rootMargin: '0px 0px -40px 0px'`）播一次揭示——四页的板块容器并不统一（总览与数据页是 `section`、功能清单是 `.split`、流程图是 `.stage`），所以由脚本统一打标，不在四个 HTML 里各写一遍，`.pager` 与页脚跳过。藏起来同样只认 JS 自己加的 `html.reveal-on`，脚本没跑到就是全部可见。业务流程图页另有一条 `dash-march` 走线动画，只加在本来就是点线的旁路边上（`stroke-dasharray: 5 4`，偏移量 `-18` 是这个周期的整数倍，循环接缝看不出来），实线一律不动——这张图里虚线和点线是有含义的（蓝虚线＝写存储，灰点线＝旁路），选中时把实线改成虚线会和图例打架，所以选中只加粗。减弱动效与打印下这些全部关掉（实测：`prefers-reduced-motion: reduce` 下进场时长压到 `1e-05s`、`scroll-behavior` 变 `auto`、揭示内容 `opacity: 1`；切 `print` 后 `path.dash` 的 `animation-name` 变 `none`）。

## 功能

- 添加任务，回车或点击「➕ 添加任务」
- 多清单分开：清单以标签页的形式排在输入框上方（每个标签带一个「还剩几件待办」的小角标），点一下就整页换成那个清单的任务。点「＋ 新建清单」新建（最多 12 个、名字最多 12 个字），点右侧的「⋯」可以重命名或删除当前清单——删除时里面的任务会先进回收站（30 天内还能恢复），其他清单不受影响，且至少会留一个清单。默认那个清单沿用老键名，所以升级前存下的任务会原样出现在「我的清单」里，不需要迁移。快速添加、筛选、统计、日历、回收站都只看当前清单，切来切去互不干扰
- 任务跨清单搬运：展开任意一条任务的详情，下面有一行「移到其他清单…」的下拉，选中就搬过去——备注、子任务、附件、置顶、重复、提醒都一起带走，6 秒内可撤销；批量管理里选中多项后，工具条上同一颗下拉可以一次搬好几条。只有一份清单时这两处都不会出现（批量那颗会置灰）
- 清单排序：输入框上方那排清单标签可以直接按住往左右拖，拖动时会在该落下的位置显示一条竖线，松手即生效；手机上同样能拖。位移不到 6 个像素仍算「点开这个清单」，不会误改顺序
- 批量粘贴建任务：在输入框里直接粘贴一段多行文字（用换行、`、`、`，`、`,`、`；`、`;` 分隔都行），会自动弹出「批量添加」面板；也可以点输入框下方的「⧉ 批量粘贴」手动展开。每一行变成一条待确认的任务，面板里能逐行看到结果、点 × 删掉不要的，行内照样认 `#分类`、`!高`、`@周五`、`~每周` 这套快速添加语法；没写属性的行会沿用上方当前选好的优先级、到期日、分类、重复。一次最多 50 条，超出的会截断并提示。点「添加这 N 条」一次性入库（支持 6 秒撤销），`Ctrl+Enter` 等同于点添加，`Esc` 收起
- 任务附件：展开任务详情，最下方是「附件」区，点「 添加附件」选文件（可多选）就能挂到这条任务上。每条任务最多 8 个附件、单个最大 5 MB，行上会显示文件名、大小和「下载」「删除」两个按钮，收起详情后任务行上留一个回形针标记。附件本体存在浏览器本地的 IndexedDB（`todo-files`）里，不上传到任何服务器，任务数据本身只记一条文件名/大小的元数据；删掉附件或删掉任务后，对应的文件会在页面空闲时自动回收，回收站里还留着的任务其附件不会被回收。要带到别的设备上，用页面底部的「⬇ 导出备份」，附件会一起打包进 JSON（见「数据存储」）
- 打卡热力图与本周小结：「数据统计」卡片底部新增两块。「本周小结」用四个格子给出本周完成数、比上周多/少几个、这周有几天打了卡、最活跃是星期几，下面一句话带上连续打卡天数。「打卡热力图」是近 20 周、周一开头的方格图（一格一天，颜色越深当天完成得越多，还没到的日子留空，今天带一圈描边），鼠标悬停能看到「10月8日：完成 2 个」。两块都按任务的完成时间统计，一条完成记录都没有时自动隐藏，不影响折叠
- 一句话快速添加：在输入框里一行写完，用符号带出属性——`#分类`、`!高`/`!中`/`!低`（`!高优先` 这种写法也认）、`@今天`/`@明天`/`@后天`/`@大后天`/`@周五`/`@下周三`/`@10-20`/`@2026-10-20`、`~每天`/`~每周`/`~每两周`/`~每月`。不带符号的自然说法（「明天」「每周一」「10-20」）也认，全角符号（`＃！＠～`）同样有效。输入时会有一行提示实时显示识别结果，认不出来的部分照原样当任务名。示例：`写周报 #工作 !高 @周五 ~每周`
- 优先级：高 / 中 / 低，用不同颜色标识，添加前在「优先级」处选择；快速添加里的 `!高` 会覆盖这里的默认选择
- 到期日：添加时可选填「到期日」（也可在编辑时改），列表上显示「逾期 N 天 / 今天到期 / N 天后到期 / 10/14 到期」，逾期为红色
- 重复任务：给任务设置「每天 / 每周 / 每月」，勾选完成后会自动排出一条下一次的任务（到期日顺延；已经逾期的从今天往后推，不背旧账；每月按当月末日夹紧；没填到期日的重复任务照样重新排出一条）。完成的那条仍保留在历史里参与统计，列表上重复任务带循环图标标记
- 按日期筛选：全部 / 已逾期 / 今天到期 / 未来 7 天 / 无日期，筛选结果计数显示在按钮上，选择会被记住
- 分类 / 标签：给任务打分类，最多 4 个（输入框会联想已有分类、输入新名字即新建，空格 / 逗号 / 顿号分隔可一次填多个）；列表上方「按分类筛选」可切换，计数与日期筛选叠加生效；快速添加里连写 `#工作 #学习` 可一次打两个分类；自带的首批清单已按 自媒体 / AI工具 / 项目开发 / 考证备考 / 理财赚钱 / 健康形象 / 生活杂事 分好类
- 分类管理：「按分类筛选」那一行最右边多了一颗虚线框的「管理分类」，点开是一个面板，把用过的分类按字母顺序列出来，每条写着「N 项待完成 · M 项已完成」，右侧三颗操作：「改名」（行内变成输入框，回车或点「保存」；改成已经存在的名字就等于合并这两个分类）、「合并到…」下拉（只有一个分类时禁用）、「去掉标记」（从所有任务上摘掉这个分类，任务本身一条都不删）。这些改动在**所有清单**里一并生效，回收站里躺着的那些年同名分类也跟着改；改完 6 秒内可撤销。面板上的数量只数各清单的任务，不含回收站
- 搜索：列表上方「搜索任务或分类…」按关键词过滤任务文字与分类名（不区分大小写），与日期、分类筛选叠加生效；有内容时出现清除按钮，Esc 也能清空
- 拖拽排序：按住行左侧的把手上下拖动即可调整顺序，鼠标与手机触摸都支持；被筛选隐藏的项位置不变
- 任务置顶：点行右侧的图钉按钮把任务钉到列表最前面（再点一下取消，取消后它留在原位不再自动跳）；置顶的任务行会有一个黄色图钉标记，键盘模式下按 `P` 也能置顶 / 取消置顶当前选中的任务
- 今日专注 + 连续打卡：今日条显示「🔥 连续打卡 N 天」（每天至少勾完一项就算连着，今天还没完成不打断，从昨天往前数；断一天则重新计）和「今天要做 N 项」（今天到期 + 已逾期）；点「只看今日」只列出这两类任务，再点「退出今日专注」返回。开启时会自动把日期筛选切回「全部」，免得和「今天到期」叠加后列表空掉，状态会被记住。窗口宽到 1040px 以上时，整条今日专注会搬到右侧信息栏最上面的「今日专注」卡片里（三行数据各占一行、按钮铺满一行），窄下来又回到清单上方原来那条横条
- 备注与子任务：点行右侧的 ▾ 展开，可写最长 500 字的备注、勾加最长 120 字的子任务（回车即保存，可勾选、可删除）；收起后行上会留一个备注小图标（鼠标悬停看前 60 字）和一个「已完成 / 总数」进度标记；重复任务排出的下一条会带上同样的备注与子任务
- 勾选完成：文字加删除线，并进入「已完成任务历史」（记录完成时间，可按日期筛选、可折叠）
- 编辑任务：点行内 ✎ 或直接双击任务文字，回车保存、Esc 取消
- 删除单条、清空已完成、全部清空（后两者需二次确认）
- 误删可撤销：删除、清空已完成、全部清空、导入备份之后，屏幕下方会出现 6 秒的「↺ 撤销」条，点一下就把整份列表还原到操作之前，过期自动消失
- 恢复已完成：「已完成任务历史」里每条右侧多了一个 ↩ 按钮，点一下把这条任务放回未完成列表（会顺手清掉历史面板的日期筛选，免得放回的任务看不到）
- 「隐藏已完成任务」：点红色按钮，或点绿色的「已完成」统计卡片
- 统计卡片显示待完成 / 已完成数量，底部显示任务总数
- 数据统计：独立的「数据统计」卡片给出完成率、已逾期 / 今天到期 / 未来 7 天的数量，按分类与按优先级的完成进度条，近 7 天每天完成几个的柱状图（今天那根是绿色），以及本周小结与近 20 周打卡热力图；统计的始终是当前清单的全部任务，不受筛选影响；点右上角箭头可折叠，折叠状态会被记住
- 导出 / 导入备份：页面底部「⬇ 导出备份」把**所有清单**的任务、回收站和附件一起存成一个 JSON 文件，「⬆ 导入备份」从该文件恢复（导入会覆盖当前全部清单，会先弹确认，导入后 6 秒内可撤销；旧版备份和只有一份任务数组的老文件也照样能导，会并进「我的清单」）
- 到期提醒：有任务逾期时，列表顶部出现红色横幅「有 X 项已逾期，还有 Y 项今天到期」，带一个「只看逾期」按钮；也可以开启浏览器通知（每天最多弹一次，避免打扰）
- 精确提醒：展开任务详情，多一行提醒设置——用日期时间选择器挑一个具体时刻，点「设提醒」生效（「1 小时后」「明天 9 点」两颗快捷按钮只负责把时间填进选择器，还要再点一下「设提醒」；选了已经过去的时间会就地提示，不会静默失效）。到点后页面最上方滑出一条黄色处置条，列出到点的任务，每条给「稍后 10 分钟」和「知道了」两颗按钮，多于一项时还有「全部知道了」，同时尝试发一条浏览器通知并「叮」一声。设了提醒的任务行上会挂一个铃声标记（写作「今天 15:30」「明天 9:00」「10月14日 20:00」），时刻已过还没处置的标记变红；日历的格子悬停提示里也会带上「N 项设了提醒」。提醒扫的是**所有清单**，在「生活」里设的提醒，哪怕正看着「工作」也照样弹，处置条上会标注「（在「生活」）」；弹过的记在本地不再重复骚扰，改了时刻则重新计；错过超过 3 小时就不再补弹。任务被勾完成、删掉、搬走或改了时间，处置条上那一条会自己消失，「知道了」则顺手清掉这条提醒
- 日历月视图：独立的「日历视图」卡片，周一开头；格子上角标当天共几件（红点 = 逾期，青点 = 当天到期，绿点 = 当天完成过）；点某一天，清单就只看那天到期的任务（再点一下取消），点「＋」直接添加那天的任务，也有「回到本月」
- 回收站：删除的任务先进回收站，保留 30 天、上限 200 条，随时可恢复或彻底清空；备份文件也会带上回收站内容
- 番茄钟：今日条上的「番茄钟 25 分钟」一键开始专注倒计时，标题栏同步显示剩余时间，完成后「叮」一声并计入「今日专注 N 轮」；时长可改——点旁边的 ▾ 在 25 / 45 / 60 分钟里选，或在「5–120」里填自定义分钟数，选择会被记住（宽屏的「今日专注」卡片里这个下拉是就地展开、占满卡片一行，不会因为信息栏会滚动而被裁掉）
- 专注后的休息：一轮专注跑完会弹出「这一轮完成了」，给「开始休息 5 分钟」和「跳过这次休息」两个选择；休息计时中今日条上的按钮变绿并显示「休息 MM:SS · 点击结束」，跑完再弹「休息结束了」问要不要开始下一轮。休息满一次计入「今日专注 N 轮 · 休息 M 次」，提前点结束则不计；两条建议都可以点 × 或「稍后再说」关掉
- 番茄钟绑定任务：展开任务详情点「专注这一项」，这一轮倒计时就绑在这条任务上（今日条上出现「本轮专注：xxx」的胶囊，点 × 可解绑；跑完一轮自动给这条任务记 1 轮，然后继续绑着它跑下一轮）。被绑过的任务行上会挂一个黄色「N 轮」标记，悬停显示「在这项上专注了 N 轮，约 M 分钟」；详情里也有一行「已累计 N 轮，约 M 分钟」。「数据统计」卡片底部新增「番茄钟投入」，按轮数从多到少列出最费时的几项（最多 6 条），下面汇总「一共 N 轮、约 X 小时」。绑定只存在当前页面里：切换清单、这条任务被勾完成或删掉，绑定就自动松开；计时中途换绑下一条，倒计时不会重置；提前结束的计时不计入
- 按优先级筛选：日期、分类之外新增一行「按优先级筛选」（全部 / 高 / 中 / 低，带计数），与日期、分类、搜索叠加生效，选择会被记住
- 逾期一键顺延：逾期任务的行上多了个闹钟按钮「推到今天」，一点把到期日改成今天；展开详情里还有「顺延 1 天」（没填日期的会设为明天）；批量模式下选中多项可一起「顺延 1 天」。这些操作都支持 6 秒撤销
- 批量整理：点「批量管理」进入多选模式，勾选后可一键完成 / 放回 / 顺延 / 删除 / 统一设分类，「全选」作用于当前能看到的任务（「已完成任务历史」折叠起来时不会选到里面的项）；「放回」把选中的已完成任务退回未完成，「彻底删除」只清掉选中的已完成任务、不进回收站（这两颗按钮只在选中项里有已完成任务时可点）
- 键盘快捷键：`/` 跳搜索、`N` 跳新建、`↑↓` 或 `J K` 选任务、`空格` 完成 / 放回、`Enter` 编辑、`P` 置顶 / 取消置顶、`Delete` 删除（进回收站）、`Esc` 取消；批量面板里 `Ctrl+Enter` 一次添加、`Esc` 收起；页面底部「键盘快捷键」可查看速查表
- 打印清单：页面底部「🖨 打印清单」先给出「打印选项」小面板，可勾选「只打未完成」和「只打今天」（两个选择都会被记住，之后直接 Ctrl+P 也照这个来），再点「开始打印」调起系统打印。打印时自动只输出清单本身——输入框、筛选、按钮、统计等界面元素都会隐藏，每行带上勾选框，可以直接打印出来当纸质清单用
- 外观：一个主色（深邃黑 `#111827`）派生出全部状态色，屏幕上只有这一个强调色；卡片是实心面 + 一圈细描边 + 两级轻投影，圆角 12 / 8 / 6 三档；「添加任务」和各处激活态都是同一颗实色主色按钮，标题是纯色粗体，任务行按优先级染一点淡底色。整体效果跟着主题和背景配色一起变，功能与布局不受影响
- 界面动效：进场只用一条曲线 `cubic-bezier(.22, 1, .36, 1)`（`.7s`），悬停是裸的 `.2s`、面板展开 `.3s`，全站没有第二条缓动；标题「我的待办清单」逐字模糊进场（每个字 80ms 依次起步，`blur(10px)` → 中途 `5px` 且反向抬起 5px → 落位清零），首屏三块（标题 / 录入卡 / 清单卡）按 `.1s` 步进排队淡入上移；往下滚时「数据统计」「已完成任务历史」「日历」三块进入视野播一次揭示，播过就固定住、往回滚不再重播；页面底多了一层会跟着鼠标点亮的点阵（详见下面「技术」）。系统开了「减弱动效」时以上全部关掉，点阵只留静态底色，内容一律直接可见
- 深色模式：标题右上角的圆形按钮三态切换「跟随系统 → 浅色 → 深色」，跟随系统时按系统的深浅偏好自动变化；选择会被记住，下次打开在渲染前就定好主题，不会闪白
- 换背景：深色模式按钮旁边多了一个图片按钮，点开是背景面板。上半部分是 8 套预设配色——青绿 / 雾蓝 / 晨橙 / 抹茶 / 紫雾 / 玫瑰 / 米砂 / 石墨，每套都配了浅色与深色两个版本，跟着主题走；每套都不是一块纯色，而是「这套主题色的三团光斑 + 一层由上而下的基础渐变」，所以页面底是有点透光感的。下半部分「上传图片」可以拿自己的一张图当背景，图片只在本地处理：先缩到最长边 1600px、再压成 webp 存进浏览器，不上传到任何服务器，实在放不下会提示换一张，「清除图片」即回到预设配色。图上会盖一层半透明遮罩，所以不管换成哪张图，文字都还读得清。配色与图片的选择都会被记住
- 响应式：手机上输入框与按钮竖排，所有可点区域不小于 44px；窗口宽到 1040px 以上时页面自动变成两栏——左边还是那条窄窄的录入与清单主栏（最宽 768px，不会因为屏幕变大就拉成一行超长文字），右边多出一条**粘性信息栏**，从上到下是「今日专注」「数据统计」「已完成任务历史」三张卡片，跟着滚动停在视野里，不用再滚过整个列表才能瞄一眼完成数、打卡情况和番茄钟；信息栏自己太高时内部单独滚动。窄下来（含手机、平板竖屏）自动回到原来的单列，今日专注也搬回清单上方。手机加到主屏或有刘海时，页面内边距会自动避开安全区

## 数据存储

全部数据保存在浏览器本机，不上传到任何服务器。`localStorage` 里：`todo.lists` 存清单名册（`{ v: 1, active, lists: [{ id, name }] }`），任务按清单分键存放——默认清单沿用老的 `todo.tasks`，其余清单是 `todo.tasks.<清单 id>`，所以老数据不需要迁移就会出现在「我的清单」里；`todo.prefs` 存偏好（筛选条件、是否隐藏已完成、今日专注开关、统计卡片折叠、主题、背景配色、番茄钟时长、打印选项等），`todo.bgimg` 单独存自选的背景图（那串 base64 有几百 KB，分开存就不会在每次保存偏好时重写它），`todo.trash` 存回收站，`todo.pomo` 存今天的番茄钟轮数与休息次数（`{ day, n, br }`，换一天就重新计），`todo.reminded` 存已经弹过的精确提醒（`{ 任务id: 那次提醒的时刻 }`，只用来防止同一次提醒重复骚扰，清掉也不影响任务本身），`todo.seed` 只记录内置首批清单是否已导入过。任务的 `att` 字段只存附件的元数据（id / 文件名 / 类型 / 大小 / 时间），**文件本体存在 IndexedDB 的 `todo-files` 库、`files` 仓库里**（以附件 id 为键）——`localStorage` 装不下二进制，而且每次保存任务都重写一遍 base64 会很慢。删附件、删任务、清空回收站之后，没人引用的文件会在页面空闲时自动回收。注意 `localStorage` 和 IndexedDB 都按「协议+域名」隔离，本地双击打开与在线地址是两份互不相通的数据。换浏览器、换设备或清除浏览器数据都会导致任务与附件丢失；此页面没有账号与同步功能。需要长期保存或跨设备迁移时，用页面底部的「⬇ 导出备份」。

备份文件是标准 JSON（`{ app, version: 2, exportedAt, lists, trash, files? }`，缩进两格）。`lists` 是清单数组，每项 `{ id, name, tasks }`；`tasks` 里每条除了文字、优先级、到期日、分类、重复之外还带 `note`（备注）、`subs`（子任务数组，每项有 `text` 与 `done`）、`pin`（是否置顶）、`att`（附件元数据）、`focus`（在这项上跑满过几轮番茄钟）和 `remind`（精确提醒的时刻，毫秒时间戳，`0` 或没有这个字段就是不设提醒）。`files` 只在真有附件要打包时出现，形如 `{ "<附件 id>": { name, type, data } }`，`data` 是 base64 的 data URL；单个超过 2 MB 的附件、或打包后整体超过约 12 MB 时会留下不打包并在导出后提示「N 个大附件没打包」，这类附件只留在原机上。`version: 1` 的老备份（只有一包 `tasks`）甚至只有一份任务数组的更老文件都能直接导入，会被并进默认清单；缺 `note`/`subs`/`pin`/`att`/`focus`/`remind` 字段会补成默认值。导入时会校验字段形状，日期对不上下文的脏数据（如 `2026-13-45`）会被清成「无到期日」而不是顺延到别的日子，`focus`/`remind` 里的负数和非数字会被清成 0（`focus` 最多记到 999 轮），回收站里超过 30 天的条目导入时直接丢弃。

## 技术

纯 HTML + CSS + JavaScript，单文件，零依赖（无框架、无 CDN、无构建步骤）。图标为内联 SVG。附件的二进制内容用浏览器自带的 IndexedDB 存，因此「零依赖」仍然成立——没有任何外部脚本或字体。

配色集中在文件顶部 `:root` 的 CSS 变量里，分三层。最底是色阶：**一个主色** `--primary: #111827` 派生全部状态档——悬停 `lighten(+30)` = `#2f3645`、按下 `darken(-20)` = `#000413`、辅助 `darken(-10)` = `#070e1d`、浅档 `lighten(+60)` = `#4d5463`、更浅 `lighten(+80)` = `#616877`，加减都是 RGB 三通道等量增、255 封顶，没有一档是手挑的颜色；中性色阶不自造，浅色主题借用 Tailwind Gray、深色主题借用 zinc。语义色只留数据编码那一组：玫红（高优先级 / 危险操作 / 逾期）、琥珀（中优先级）、深绿（低优先级 / 已完成）。中间是语义变量（`--accent` 与它的 `-hover` / `-pressed`、`--surface`、`--bg-raised`、`--bg-hover`、`--divider`、`--card-border`、`--page-bg`、`--on-accent`、`--tint-fill` / `-hover` / `-pressed` / `-border`、`--shadow-*`、`--scrim` 等），组件样式只引用这一层，不写死色号；`[data-theme="dark"]` 里把这一整套重定义一遍（连带 `--gray-*` 九档），深色模式即整体反转，不必逐条改规则。同时设了 `color-scheme`，浏览器滚动条与表单控件会跟着换。想换整套配色，只改这两段的主色与由它推出来的档位即可。热力图用的四档色（`--hm0`–`--hm3`）也放在这两段里，浅色主题越深表示完成得越多、深色主题越亮表示完成得越多，空格子另有一圈 `--hm-line` 描边保证格子形状看得见。

外观这一版是按「后台管理规范」重写的（这套规范原本写给 Naive UI 的桌面后台，这里搬的是它的判断，不是它的 60px 顶栏和 240px 侧栏），DOM 与类名一行没改，全部差异都落在 `:root` 那一段：

- **深色模式换主色**：规范第二条是「深底配深主色 = 看不见」，所以 `[data-theme="dark"]` 把 `--accent` 换成主色的 light 档。规范给的 light / lighter 是 `+60` / `+80`（`#4d5463` / `#616877`），但 `#616877` 压在深色表面 `#18181c` 上当文字只有 3.15:1，过不了 AA，于是沿用同一个通道加减公式再往上推三档：`--primary-lift: #a7aebd`（压在 `#18181c` 上 7.9:1）、`--primary-lift-2: #c5ccdb`、`--primary-lift-3: #e3eaf9`。深色主题的实心按钮是 `#a7aebd` 底 + `#101014` 字，8.4:1。
- **屏幕上只留一个强调色**：主色的透明着色档用 8 位 hex 表达，不逐色手调 rgba（浅色 `#11182715` / `25` / `35` / 描边 `40`，深色 `#a7aebd20` / `30` / `40` / `50`）。玫红 / 琥珀 / 深绿三组保留，因为它们在编码信息（优先级、逾期、完成），不是第二个装饰色。
- **尺度定死**：圆角只有三档——12（卡片、弹层）/ 8（输入、按钮）/ 6（小件）；动效 `.2s`（悬停）与 `.3s`（面板）；滚动条 4px、滑块 `rgba(0, 0, 0, .15)`（深色 `rgba(255, 255, 255, .15)`）、圆角 2px；投影两级——卡片 `0 1px 3px 0 rgb(0 0 0 / .1), 0 1px 2px -1px rgb(0 0 0 / .1)`，浮起来的层 `0 25px 50px -12px rgb(0 0 0 / .1)`（深色换成 `.55`），按钮不再带投影。z 轴五档写进变量：`--z-popover` 1000 < `--z-bar` 1500 < `--z-undo` 1510 < `--z-scrim` 2000 < `--z-dialog` 2100，组件里不再出现临时的层级数字。间距落在 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 的刻度上。
- **玻璃与渐变全部去掉**：带模糊的 `backdrop-filter` 从 6 处（卡片 / 弹层 / 侧栏三对，含 `-webkit-` 前缀）降到 0，卡片、弹层、侧栏都改成实心 `--surface` + `--card-border` 细描边；12 处按钮渐变、8 处进度条 / 日历柱 / 删除按钮渐变拉平成实色；标题的渐变字连 `@supports` 包裹一起删掉，回到 `color: var(--gray-800)`；卡片顶部那条 1px 内高光 `--card-sheen` 取消。唯一还留着 `backdrop-filter` 的地方是 `@media print` 里那条 `none !important` 复位，它现在是个空操作，留着是因为整段打印规则一个字节都没动。
- **旧变量名留成别名**：组件里有一百来条规则按 `--teal-600` / `--teal-700` / `--teal-800` / `--teal-50` 引用主色，这一版没有去改名，只把它们定义成 `var(--accent)` / `var(--accent-hover)` / `var(--primary-pressed)` / `var(--bg-raised)`，所以换主色仍然只动一处。`--teal-50` 值得单独记一笔：它原本是一块「主色浅底」，这次没跟着换成主色的 8% 透明档 `--tint-fill`——半透明底压在光斑背景上会把 `.focus-card` 那类容器染暗，实测让琥珀色文字掉到 3.7:1；还是用实心的淡档底（浅色 `#f9fafb`、深色 `#27272a`）才读得清。
- **字体栈**换成规范那一套再补中文回退：`'Inter', -apple-system, BlinkMacSystemFont, 'Segoe UI', Roboto, 'Helvetica Neue', Arial, 'Noto Sans', "PingFang SC", "HarmonyOS Sans SC", "MiSans", "Microsoft YaHei", sans-serif`，`-webkit-font-smoothing: antialiased` 照旧。
- **全局三件小东西按规范重定**：滚动条见上；`::selection` 走 `--tint-pressed`；`:focus-visible { outline: 2px solid var(--accent); outline-offset: 2px }`，另外 3 处自画的 `outline` 和 12 处自画焦点阴影统一改用 `--accent`。
- 可靠性没被牺牲：`@media print` 那一段与改前逐字节相同（它本来就是 `#fff` / `#000` / `#ddd` 的实色复位，不依赖任何被删掉的变量）；`prefers-reduced-motion: reduce` 照旧把全部动画与过渡关掉；8 套预设背景的 16 条 `--bgl` / `--bgd` 声明也与改前完全一致。

### 动效与点阵背景

这一版的动效是照着参考站的做法重做的，四条纪律：进场只认一条曲线 `--ease-enter: cubic-bezier(.22, 1, .36, 1)`（配 `--dur-enter: .7s`），悬停一律裸 `.2s`，面板展开 `.3s`，全文 `ease-out` 出现 0 次（`grep -c "var(--ease-enter)" index.html` = 16 行，`grep -c ease-out` = 0）。标题逐字进场把 `h1` 的文本拆成 6 个 `.blur-text-segment`，每颗 `animation-delay` 递增加 80ms，`@keyframes blur-in` 三段式：0% `blur(10px)` / 下移 50px、50% `blur(5px)` / 上抬 5px、100% 归零，播完加 `.bt-done` 把 `filter` 整个撤掉——留着会让这六颗字长期吃一层 GPU 滤镜。

滚动揭示用 `IntersectionObserver`，参数 `{ threshold: .12, rootMargin: '0px 0px -40px 0px' }`，命中即加 `.visible` 并 `unobserve`，所以只播一次、往回滚不重播。这里有个必须记住的坑：**「把内容藏起来」这件事只认 `html.reveal-on` 这个类，而这个类由脚本在观察器挂好之后才加**。整页只有一个 `<script>`，前面任何一句抛错都会让这段跑不到；要是 CSS 无条件就把 `.reveal` 设成 `opacity: 0`，用户看到的就是三块永久空白。所以顺序是「先挂观察器 → 再放行首屏内已有的块 → 最后 `add('reveal-on')`」，外面还包一层 `try/catch` 兜底 `showAll()`；减弱动效或浏览器没有 `IntersectionObserver` 时直接 `showAll()` 且不加那个类。打印路径另有一道 `!important` 复位（`html.reveal-on .reveal { opacity: 1 !important; transform: none !important }`），实测用 CDP 的 `Emulation.setEmulatedMedia({ media: 'print' })` 切媒体：说明站第一屏外那张卡在屏幕媒体下是 `opacity: 0 / translateY(28px)`，切到 print 变成 `1 / none`，切回来又回到 `0`。折叠面板也不打架：`#history` 是 `display: none`，展开后观察器照样补上 `.visible`（实测 `op` 从 0 变 1）。

点阵背景是一块 `position: fixed; z-index: -1; pointer-events: none` 的 canvas，`aria-hidden`，参数与参考站一致：点径 5px、间距 15px、邻近半径 120px、触发速度 100px/s、冲击半径 250px、强度 5、最大速度 5000、回位 1500ms；弹簧用 `1 - Math.pow(1 - p, 3) * Math.cos(p * 4.5)`，180ms 推开 + 200ms 延迟 + 1500ms 回位，`mousemove` 50ms 节流，DPR 缩放 + 一个共享 `Path2D` + `ResizeObserver`。两点与参考站不同，都是量出来的决定：一是**点击涟漪加了闸门**——参考站是登录页，点哪儿都算背景，而这是清单页，一天要勾几十次完成框，所以落在 `.card, .head, button, a, input, select, textarea, label, li` 上的点击不起涟漪；二是**点不带色相**，深浅两主题各只有一对 `--dot-base` / `--dot-hot`（浅 `#d4d9df` / `#c8ced6`，深 `#27272a` / `#4a4a52`），效果全靠运动本身。

物理指标不能在有头浏览器里量（虚拟时间会饿死 `requestAnimationFrame`，CSS 过渡和观察器回调也一样饿），所以把引擎原样抽进 Node 用可控时钟逐帧驱动，稳定复现：1280×900 共 2880 个点，静置 90 帧重绘 **0** 次（空闲不烧 CPU）；快速划过时最多 224 个点被推开、峰值位移 149.4px、出现在第 83ms、随后回到原位（峰值位移 0）；空白处点击涟漪带动 484 个点、峰值 336.1px；**点在卡片上时重绘 0 帧、位移 0**（闸门生效）；慢速移动（10px/s）不推点，只让邻近点变色——同一帧里出现 18 种颜色、无指针时只有 1 种，说明按距离做了插值。减弱动效下重跑同一套：位移与涟漪全为 0，只保留点亮。

页面背景是 `--page-bg`，它指向成对的 `--bgl`（浅色版）与 `--bgd`（深色版），预设配色只是用 `[data-bg="mist"]` 这类选择器把这一对变量整体换掉，所以新增一套预设仍然只要写两条背景。这两条现在都是四层叠起来的：三团主题色的 `radial-gradient` 光斑（左上、右上、底部中央）压在一层 `linear-gradient(165deg, …)` 基础渐变上，光斑的透明度浅色主题在 `.12`–`.22` 之间、深色主题在 `.08`–`.13` 之间，基础渐变的明暗区间和上一版一致，因此换成光斑背景不会整体变亮或变暗。背景面板里那八个色板方块就是把 `--bgl` / `--bgd` 原样画成自己的背景（`[data-theme="dark"] .sw .sw-c` 用 `--bgd`），预设改了色板自动跟着改，不用另写一份颜色。自选图片走另一条路：`html[data-bgimg="1"] body::before` 一层 `position: fixed` 的图，上面叠一层 `--bg-wash`（浅色主题 `rgba(255, 255, 255, .8)`、深色主题 `rgba(8, 14, 13, .8)`），最暗的图配浅色、最亮的图配深色这两种极端情况都仍满足下面的对比度要求。

两套主题、八套预设、以及压在最暗 / 最亮图片上的情况都按 WCAG AA 校验过：文字对比度不低于 4.5:1，图标与非文字控件不低于 3:1。这一版量起来比玻璃时代准：卡片和按钮都是实面，`getComputedStyle` 读到的 `color` / `backgroundColor` 就是屏幕上真正那一层；上一版的渐变按钮与渐变字，计算值是 `transparent`，探针量到的对比度并不可信。量法是把页面塞进 `iframe` 得到 390 / 320 两种真实视口（Chromium 窗口最小约 500px，宽屏 1280 直接开），用 `localStorage` 定住主题、关掉全部动效，遍历每个带直接文字节点的元素，把它自己到根一路上不透明的 `backgroundColor` 按 alpha 合成到「薄荷光斑的中间色」（浅色 `#e3f2ee`、深色 `#0f1b19`）上再算相对亮度。这一版的结果：浅 / 深两主题，1280 下另加背景面板、任务详情、批量条、回收站、删除确认、快捷键速查表六层各量一遍，0 处不达标（窄视口每次 240 个文本节点）。上一版同法量到 9 处（浅色）/ 8 处（深色），其中真正要修的只有页面底部「键盘快捷键」那颗次要按钮——`--gray-500` 压在光斑底上 4.19:1，已改 `--gray-600`。可点区域也复核过：44px 以下的控件数量与改前一模一样（390px 下两版都是 91 个，多数是日历格右上角的「＋」这类小件），没有一个控件因为这次改样式而变小；320px 下「回到本月」一颗从 46 高变成 36 高，是改前那颗被挤成两行字才虚高到 46，它自己的 `min-height` 一直是 36px。

点阵是这一版新加的一层，所以「文字压在点上」要单独量。量法不是猜哪些文字在点上，而是遍历 `body` 下每个有直接文字节点、且已渲染的元素，从它自己往上找有没有不透明的 `backgroundColor` 或 `background-image` 把点阵挡住——挡不住的才是真压在点上，再拿它的 `color` 和**最深的那颗点** `--dot-hot` 算比值（点径 5px、间距 15px，覆盖率不到 5%，按整片都是深点算是最坏情况）。结果：两个主题各 10 处文字真的压在点上（标题六个字、副标题、「新建清单」、「共 27 个任务」、「键盘快捷键」），**0 处不达标**。浅色最差 4.77:1（16px 副标题 `#4b5563` 压 `#c8ced6`，门槛 4.5，余量 +0.27），深色最差 5.45:1（13px「新建清单」压 `#4a4a52`，余量 +0.95）；标题 36px 粗体走 3:1 大字号门槛，浅 9.27:1 / 深 8.78:1。卡片、弹层、任务行全在实心 `--surface` 上，压根不和点阵重叠。

版式用的是第三层「组件变量」：`--wrap-narrow`（单栏上限 768px）、`--wrap-wide`（双栏总宽 1132px）、`--side-w`（信息栏宽度 `clamp(280px, 26vw, 340px)`）、`--dash-gap`、`--card-gap`、`--sticky-top`，只放尺寸不放颜色，改栏宽只动这一处。两栏由 `.dash { display: grid }` 承担：默认单列，`@media (min-width: 1040px)` 才变成 `minmax(0, 1fr) var(--side-w)`，`.side` 上 `position: sticky` + `max-height: calc(100vh - 32px)` + `overflow: auto`。踩到过几个坑，都在这里记一笔：一是**网格项的 `min-width` 默认是 `auto`**，信息栏里的统计卡会被热力图、四格指标这些「压不窄」的内容撑到 363px，直接顶破 340px 的轨道（页面不出现横向滚动条，只在栏内悄悄多出一条滚动），所以 `.dash > *` 与 `.side > *` 都显式写了 `min-width: 0`；二是**日历不能搬进信息栏**——七列网格在 300px 宽的栏里每格只剩三十几像素，所以两栏里它留在主栏，右侧只放今日专注、统计与历史；三是**同一块 UI 不能有两份 DOM**，所以「今日专注」只有一个 `#today-strip`，由 `matchMedia('(min-width: 1040px)')` 在两个父节点之间搬（宽屏进 `#focus-card`，窄屏插回清单卡片的筛选条前面），搬完再 `render()` 一次同步卡片的显隐——横条里的番茄钟下拉原本是 `position: absolute` 挂在横条下面的，搬进信息栏就会被 `.side` 的 `overflow: auto` 裁掉，所以宽屏下改成 `position: static` 就地展开成一行。打印时 `.dash` 复位成 `display: block`、`.side` 连同里面的今日专注一并隐藏，输出的还是纯清单。

## 开启 GitHub Pages

1. 仓库页面 → **Settings** → 左侧 **Pages**
2. **Build and deployment** → Source 选 **Deploy from a branch**
3. Branch 选 `main`，文件夹选 **`/ (root)`** → **Save**
4. 等待约 1 分钟，页面顶部出现地址：`https://<你的用户名>.github.io/<仓库名>/`
